# 凯美瑞适配防回归说明与实车验收清单（2026-10-18 11:12）

## 这套检查保护什么

防回归，就是在后续修改或合入官方代码时，尽早发现原来能用的功能被改坏。
电脑上的检查负责确认规则和程序行为；车机验收负责确认实际画面、声音、麦克风和原车按键。两者不能互相替代。

本文是长期使用的验收规则，下面的实车表格是空白模板，不能作为已经通过的记录。README 只介绍产品功能，不放调试进度。

## 一条命令运行适配回归

在 DiPlay 根目录执行：

```bash
scripts/check_vehicle_adaptation.sh
```

需要项目使用的 Java、Android SDK/NDK、CMake，以及 Python 3。使用当前项目的本地签名配置；签名配置方法见 [构建说明](../BUILD.md)。
命令会运行 DiPlay、先锋适配及三个不依赖原包的 WeCarFlow 检查，并构建源码验证 APK。任何一步失败，命令都会返回失败，不能继续当作通过。

**源码验证 APK 不含 CarPlay 私有运行认证素材，只用于检查构建，不用于装车。** 正常车机包继续使用 `:mobile:assembleStandaloneDebug`，与本命令分开。

本地已有 WeCarFlow 原包反编译目录时，可执行完整检查：

```bash
scripts/check_vehicle_adaptation.sh --with-wecarflow-baseline
```

该模式会运行全部七项 WeCarFlow 检查，包括原包清单、仪表和播放拦截补丁的兼容性。缺少 `wecarflow/build/baseline/AndroidManifest.xml` 或 `wecarflow/apktool/` 时直接失败，不会跳过后报告成功。原包与反编译树的准备方式见 [WeCarFlow 说明](../../wecarflow/README.md)。它们不提交到公开仓库。

## 自动检查怎样运行

独立流程位于 [vehicle-adaptation.yml](../../.github/workflows/vehicle-adaptation.yml)，名称为 `Camry adaptation regression (diplay)`。

- 向 `main` 或 `codex/**` 分支推送、提出 PR，或手动触发时运行。
- 调用同一条 `scripts/check_vehicle_adaptation.sh`，避免本地与服务器维护两套用例名单。
- 使用临时测试证书，不依赖车机共享签名密钥或私有认证素材，也不会发布或安装 APK。
- 保存测试报告和执行日志；失败显示为失败，不使用“忽略错误继续”。
- 不依赖原包的三个 WeCarFlow 检查进入 CI；另外四项补丁检查由本地完整命令执行。

新增流程保留现有上游 Android 检查流程。这里没有配置仓库的分支保护规则；是否禁止合入失败提交，仍由仓库设置决定。当前分支直接推送后才开始检查，推送成功本身不代表检查通过。

## 检查项目与边界

| 功能 | 电脑检查的规则 | 仍需车机确认 |
| --- | --- | --- |
| 尺寸默认值 | 预设必须为大／250mm；实际读取和设置页显示一致；用户已保存的其他尺寸不被覆盖 | CarPlay 图标、文字及画面比例 |
| 个人配置 | 未配置时，车载热点与同一局域网的名称、密码为空 | 编辑并保存后，重开应用显示正确 |
| 日夜同步 | 默认跟随凯美瑞；保存选择；光线和定时规则；状态处理及回退 | 原车昼夜状态能否传到 iPhone 画面 |
| 连接与重试 | 有线启动超时、端口释放、取消；旧会话不能顶替新会话；关闭不等待阻塞回调 | iPhone 配对、实际重连和车机固件行为 |
| 声音与音源 | 音源恢复的时机和次数；暂停时不擅自播放；音频焦点、音轨释放和导航衰减 | MODE 回爱趣听后的听感及 iPhone 是否重新发送音频 |
| 麦克风 | 录音申请、配置、停止与资源清理；软件编码异常保护 | 实际电话对方能听见、Siri 能识别 |
| 界面交互 | 截图与画面释放共享等待预算；Surface 生命周期 | 快速切换后的流畅度、黑屏和花屏 |
| 调试与升级互斥 | 不能同时升级；旧任务不能释放新任务的保护；安装期间不能误删文件 | 真实安装、签名兼容与升级后配置 |
| WeCarFlow | 弹窗条件、前后台和内部跳页；关闭不解除保护；本次不提示；播放准备取消；仪表消息处理 | 开机后桥接与方控、爱趣听不被误启动播放 |

## 固定实车验收清单

每次验收先复制下表到单独记录，填写：日期时间、DiPlay 与 WeCarFlow 版本、车机固件、iPhone／iOS、连接方式。结果填写“通过／失败／未执行”，不要只记“已测”。
每项记录实际表现、发生时间和对应日志位置；声音问题同时记录车机当前音源和 iPhone 的播放状态。

| 编号 | 操作步骤 | 通过标准 | 结果 |
| --- | --- | --- | --- |
| A1 开机与桥接 | 重启车机，正常启动 DiPlay，连接 CarPlay，按方向盘前后曲；重复 3 次 | 桥接无需手动打开爱趣听；每次按键生效且不重复切歌；爱趣听不自行播放 | 未执行 |
| A2 基础连接 | 有线正常连接、断开、重新连接各 3 次；使用无线时补测无线连接 | 无卡死；新连接可以操作；退出后不被旧连接通知影响 | 未执行 |
| A3 音乐与导航 | 音乐连续播放 10 分钟；期间触发导航播报、暂停、继续和切歌 | 音乐与导航都有声音；播报结束音量恢复；暂停后不擅自继续 | 未执行 |
| A4 MODE 切源 | 从爱趣听音源切到其他音源，经过关闭所有源的状态，再切回；蓝牙音乐介入后停止并回切；各重复 5 次 | 切走不抢音源；切回后实际有声，按键有效；不能只凭 iPhone 播放图标判通过 | 未执行 |
| A5 电话与 Siri | 由测试人员安排一次拨出和一次接听，在通话中讲话；挂断后播放音乐，再调用 Siri | 双方都听得见；无持续抢占；挂断恢复音乐；Siri 能收到讲话 | 未执行 |
| A6 真实昼夜 | iPhone CarPlay 外观选自动，切换原车白天／夜间各 3 次，每次保持约 10 秒 | CarPlay 对应切换；当前会话内生效，无需重连 | 未执行 |
| A7 提醒与保护 | 无 CarPlay 时打开爱趣听；连接后再打开；关闭提示、内部跳页、退出再进入 | 无保护不弹；保护生效时进入应用弹；关闭仍受保护；内部跳页不重复弹 | 未执行 |
| A8 本次不提示 | 勾选后关闭，重新进入应用，断开并重连 CarPlay；随后重启爱趣听界面主进程，重新建立保护 | 主进程未重启时不再弹；主进程重启后恢复提醒；保护状态不因关闭提示改变 | 未执行 |
| A9 前后台与交互 | 音乐播放时，在 CarPlay、设置和车机主页间往返 20 次，并操作触控 | 无明显长时间卡住、黑屏或花屏；声音不中断；画面和触控恢复 | 未执行 |
| A10 配置与覆盖升级 | 新安装场景核对尺寸大／250mm和跟随凯美瑞；另在有保存配置的场景覆盖升级 | 新默认正确；已有尺寸、日夜选择、热点及配对配置按原选择保留。不要为此清除日常车机数据 | 未执行 |
| A11 重试与长时运行 | 连接过程中取消并重试 5 次；正常连接持续使用至少 30 分钟 | 没有残留连接阻止重连、重复回调或持续增长的异常；期间声音画面正常 | 未执行 |

A1—A9 任一关键项失败，都应记录为未通过；电脑检查通过不能抵消实车失败。原本待排查的 MODE 无声与电话上行问题，同样按 A4、A5 的实际结果判定，不能因新增测试而视为已修复。

## 后续修改的维护方式

1. 修改适配逻辑或合入上游后，运行统一回归命令；有原包的环境再跑完整模式。
2. 新增适配测试文件时，将它加入统一命令的用例名单；缺失文件和零用例必须保持失败。
3. 修复明确故障时，优先补能在电脑上复现的行为用例，尤其关注取消、迟到通知、快速重试和资源释放。
4. 变更默认值时同时检查预设、保存读取和界面显示，避免只修改其中一处。
5. 涉及声音、方控、画面或原车接口时，执行对应实车项；版本发布前执行完整清单。
6. 只在产品规则明确变化时修改预期，不能为了让检查变绿而删除失败断言或扩大跳过范围。
