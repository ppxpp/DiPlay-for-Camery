# DiPlay 一键反馈功能设计

日期：2026-11-04
状态：已实现，待实车验证

## 1. 目标

在 DiPlay 中提供一个匿名、低操作成本的反馈入口。用户选择问题类型、可选填写问题描述后，DiPlay 自动整理脱敏后的诊断日志并上传。后端归档反馈包，管理台按时间、类型、版本查看和下载，供工程人员定位问题。

本期只做“采集、上传、归档、查看”，不做自动根因分析、错误聚类、LLM 分析、用户回复或工单状态流转。

## 2. 入口

保留两个入口，不实现崩溃后的引导弹窗：

| 入口 | 位置 | 预填内容 |
| --- | --- | --- |
| 主入口 | Settings → Diagnostics 卡片新增“一键反馈” | 问题类型不预选 |
| 连接失败 | CarPlay 连接失败面板，在“重试/返回”旁增加次级按钮“反馈此问题” | 问题类型预选“连接”，顶部只读显示当前故障阶段 |

崩溃记录本身不再触发任何提示；如果本地存在 `crash/last-crash.txt`，仍作为普通日志文件附带。

## 3. 反馈页交互

### 3.1 页面布局

采用单页表单。页面分为上下两部分：

- **上半部：所有可操作元素**，键盘弹出后仍完整可见。
- **下半部：说明性内容**，键盘覆盖不影响操作。

```
┌────────────────────────────────────┐
│ 发送反馈                    [发送] [关闭] │
│ 问题类型：连接 ▾                     │
│ 故障阶段：热点未就绪（单行省略，仅连接失败入口） │
│ ┌────────────────────────────────┐ │
│ │ 问题描述（可选）                │ │
│ │ 发生了什么？什么时候开始？      │ │
│ │ 能否复现？                      │ │
│ └────────────────────────────────┘ │
├────────────────────────────────────┤
│ 匿名说明 / 将包含的日志内容          │
│ 待上传反馈数量                      │
└────────────────────────────────────┘
              [ 键盘占下半屏 ]
```

具体约束：

1. 发送按钮在顶栏右侧，不放在页面底部，保证键盘弹出后仍可见、可点。
2. 问题类型用一行选择器展示，点击弹出 6 个大尺寸选项；不在页面上平铺多个分类按钮。
3. 连接失败入口额外显示一行只读故障阶段，单行省略；普通入口不显示。
4. 描述输入框占据上半部剩余空间，建议 3–5 行，超出后在输入框内滚动。
5. 描述接近 2000 字时才显示字数计数。
6. 下半部只放匿名说明、将包含内容摘要和待上传数量。
7. 顶部交互区固定为屏幕可用高度的约 40%，页面使用 `adjustPan|stateAlwaysHidden`；键盘只覆盖下半部，不压缩上半部布局。
8. 极端矮屏或大字体时（可用高度低于 360dp）隐藏下半部说明，只保留顶栏、类型选择器、故障阶段和描述输入框。
9. 输入框、分类选择器和发送按钮都位于上半部，系统键盘不会遮挡它们。

### 3.2 问题类型

必选，默认不选中。连接失败入口预选“连接”。

分类：

- 连接
- 画面
- 声音
- 导航与仪表
- 方控与车控
- 其他

未选择类型时“发送”呈不可用样式；点击时提示“请选择问题类型”。

### 3.3 问题描述

可选，最多 2000 字。占位文案：

> 发生了什么？什么时候开始？能否复现？

描述留空也允许提交。页面明确提示：描述能帮助更快定位，但可以不填。

### 3.4 提交后的状态

```
编辑中
  └─ 点击发送
       ├─ 整理中（禁止关闭页面，通常 1–3 秒）
       │    ├─ 失败 → 留在当前页，提示“无法整理诊断信息”，可重试
       │    └─ 成功 → 反馈包进入本地队列
       │         ├─ 有网络 → 正在上传
       │         │    ├─ 成功 → 显示 8 位反馈编号 +「完成」
       │         │    └─ 失败 → “已保存，联网后自动上传” +「立即重试」「查看记录」「完成」
       │         └─ 无网络 → “已保存，联网后自动上传” +「立即重试」「查看记录」「完成」
       └─ 队列已满（5 条）→ 提示“已有 5 条反馈等待上传，请联网后再试”
```

规则：

- 整理阶段较短，不允许关闭，避免生成不完整的包。
- 进入队列后用户可以立即离开页面，后台上传和重试不依赖页面存活。
- 反馈编号在生成反馈包时确定，取 32 位随机十六进制 ID 的前 8 位展示。
- 服务端明确拒绝的请求（4xx，408/429 除外）标记为失败，保留 7 天，可手动重试或删除。
- 网络错误、超时、429、5xx 自动重试。
- 上传成功时始终写入一条本地“已发送”记录（编号、时间、类型、状态）；如果用户还在反馈页，同时立即显示“已发送”和反馈编号。
- “已发送”表示客户端收到服务端 201/200 成功响应，不代表问题已经被人工处理。
- 诊断页“一键反馈”按钮下方显示“有 N 条反馈等待上传”，并提供“查看记录”入口。

### 3.5 网络状态提示

反馈上传必须依赖车机自身可访问互联网的网络。无线 CarPlay 占用的本地 Wi-Fi 通常没有外网，不能把“已连接 Wi-Fi”当成“已联网”。

反馈页常驻一条网络状态：

| 状态 | 文案 | 发送按钮 |
| --- | --- | --- |
| 有可用互联网 | 车机已联网，发送后会立即上传 | 发送反馈 |
| 无可用互联网 | 车机当前没有可用网络，反馈会先保存在本机，联网后自动上传 | 保存，联网后发送 |
| 检查中 | 正在检查网络… | 不可用 |

补充规则：

- 使用现有 `InternetNetworkSelector.select()` 判断是否存在经过验证的互联网网络，而不是只查 `ConnectivityManager` 的连接状态。
- 页面在 `onResume` 时重新检查网络；网络从无到有时，立即刷新状态并允许重试。
- 无网络时点击发送不报错，正常入队，并显示“已保存，联网后自动上传”。
- 在反馈记录页点击“立即重试”时，如果仍无可用互联网，弹出提示：
  > 车机当前没有可用网络，无法上传。请先让车机连接可上网的 Wi-Fi，或确认车机 4G/5G 已开启。
  按钮为「打开网络设置」「知道了」。打开设置依次尝试 `Settings.ACTION_WIFI_SETTINGS`、`Settings.ACTION_WIRELESS_SETTINGS`、`Settings.ACTION_SETTINGS`，不可用时提示用户从车机设置中手动开启网络。
- 页面底部说明明确写出：反馈上传需要车机自身能访问互联网；仅连接 iPhone 的 CarPlay Wi-Fi 通常无法完成上传。
- Diagnostics 卡片的“一键反馈”说明同步写明“需要车机联网；无网络时会先保存”。
- `FeedbackUploadWorker` 每次执行前重新检查经过验证的互联网网络；没有时返回重试，不使用仅本地连接的 Wi-Fi 发起请求。

### 3.6 反馈记录页

新增 `FeedbackRecordsActivity`，用于查看待发送、发送失败和已发送的反馈。

入口：

- 设置首页（Overview）的 Diagnostics 分类卡片显示角标“N 条反馈待处理”。
- 设置侧栏的 Diagnostics 项显示同一角标。
- Diagnostics 卡片内显示“待发送 N 条 · 查看反馈记录”。
- 反馈页提交失败、待上传或已发送后提供“查看记录”。

页面分为“待处理”和“已发送”两个标签：

**待处理**

- 顶部显示网络状态条：
  - 有可用互联网：“车机已联网，可立即重试上传。”
  - 无可用互联网：“车机当前没有可用网络，待上传反馈会在联网后自动发送。”并提供“检查网络”。
- 按时间倒序展示最多 5 条待上传/重试中记录和 5 条永久失败记录。
- 每条显示类型、提交时间、描述摘要、反馈编号。
- 状态文案：
  - `PENDING`：等待联网
  - `UPLOADING`：正在上传
  - `FAILED_RETRYABLE`：上传失败，将自动重试
  - `FAILED_PERMANENT`：发送失败，需要手动处理
- 操作：
  - 立即重试：上传中不可用；无可用互联网时弹出网络提示。
  - 删除：二次确认后删除本地反馈包和记录。
  - 全部重试：有可用互联网且存在可重试记录时显示。
- 空状态显示“没有待发送的反馈”，并提供“发送反馈”按钮。
- 重试成功后，该记录移入“已发送”并提示“反馈已发送”。

**已发送**

- 展示最近 10 条上传成功的记录，仅保留反馈编号、时间、类型和“已发送”状态。
- “已发送”表示服务端已接收该反馈，不代表问题已被人工处理。
- 不保留问题描述、日志包或设备信息。
- 单条记录保留 30 天；用户可单条删除或“清空已发送记录”。
- 空状态显示“还没有已发送的反馈”。

其他规则：

- 角标数量只统计待处理记录，即待上传、上传中、自动重试和永久失败；已发送记录不计入角标。
- 上传成功或删除后角标自动减少。
- 页面在 `onResume` 时重新读取队列、已发送记录和网络状态，保证从系统网络设置返回后状态正确。

### 3.7 本地化与页面注册

- 新增字符串统一使用 `feedback_` 前缀，除 `values/` 外加入 `values-ar`、`values-es`、`values-it`、`values-ja`、`values-ru`、`values-uk`、`values-zh-rCN`、`values-zh-rTW`。
- `FeedbackActivity` 和 `FeedbackRecordsActivity` 在 `common` 的 `AndroidManifest.xml` 注册，`android:exported="false"`。
- 角标和状态文案需要提供无障碍描述。

## 4. 客户端架构

新增 `com.shilapi.xcertplay.feedback` 包，避免继续扩大 `DiPlayActivity.kt`。

| 组件 | 职责 |
| --- | --- |
| `FeedbackActivity` | 单页反馈表单、分类选择、描述输入、网络状态、提交状态 |
| `FeedbackRecordsActivity` | 未发送/失败反馈列表、重试、删除、网络提示 |
| `FeedbackBundle` | 生成精简反馈 zip、执行限制和脱敏、写入 manifest |
| `FeedbackOutbox` | 本地待发队列和已发送轻量记录，原子写入、最多 5 条待上传 |
| `FeedbackConnectivity` | 判断是否存在经过验证的互联网网络 |
| `FeedbackUploadWorker` | WorkManager 唯一任务，联网约束和指数退避 |
| `FeedbackUploader` | multipart HTTP 上传、响应码处理 |

### 4.1 反馈包生成

- 在后台线程生成，先写临时文件，校验 zip 可读后再移入队列。
- 复用 `DiagnosticArchive` 的流式写包、逐项 manifest、SHA-256 和文本脱敏能力。为该类增加可配置的单项/总大小上限，默认值保持现有完整诊断包行为。
- 生成前调用 `AsyncDiagnosticLog.awaitIdle(2000)`，尽量把待写日志落盘。
- 打包时逐条限制日志大小，避免长时间占用车机 CPU。
- App 下次启动时清理未完成的临时打包目录。

### 4.2 本地队列

- 目录：`filesDir/feedback-outbox/`。
- 每条反馈包含 `bundle.zip`、`meta.json`、`state.json`。
- 使用临时文件加 rename 原子写入，避免半成品被上传。
- 最多保留 5 条待上传或重试中的反馈；队列满时拒绝新反馈，不覆盖旧反馈。
- 状态：`PENDING`、`UPLOADING`、`FAILED_RETRYABLE`、`FAILED_PERMANENT`。
- `FAILED_PERMANENT` 不占用 5 条待上传配额，最多保留 5 条，超出时删除最旧记录；单条保留 7 天后清理。
- 上传成功后删除 `bundle.zip` 和描述内容，只向 `sent-history.json` 追加一条轻量记录。
- `sent-history.json` 最多保留 10 条、30 天，字段仅包含反馈编号、时间、类型和已发送状态。
- 已发送记录不计入待处理角标；用户可单条删除或清空。

### 4.3 上传调度

- WorkManager 唯一任务名：`diplay-feedback-upload`。
- 约束：`NetworkType.CONNECTED`。
- 退避：指数退避，首次 1 分钟。
- 自动重试在 CarPlay 会话连接中或活跃时暂缓，避免抢占带宽；用户主动提交或点击“立即重试”时直接上传。
- 每次执行前用 `InternetNetworkSelector.select()` 确认存在经过验证的互联网网络；只有本地 Wi-Fi、没有外网时返回重试，不发起请求。
- App 每次打开时补一次调度，确保重启后仍能继续上传。

### 4.4 上传请求

```
POST https://diplay.mgulu.com/api/v1/apps/diplay/feedback
Content-Type: multipart/form-data

meta:   JSON，schemaVersion=1、反馈 ID、类型、描述、入口、版本、设备、会话、bundleSha256
bundle: application/zip
```

- 使用 `HttpURLConnection`，沿用现有 `UpdateClient` 的超时和响应读取风格。
- 连接超时 10 秒，读取超时 120 秒。
- 请求体上限 6MB。
- 通过 `FeedbackConnectivity` 选中的互联网网络打开连接，不绑定到仅用于 CarPlay 的本地 Wi-Fi。
- 上传前本地校验 zip 大小和 SHA-256。
- 无可用互联网时不发起请求，直接保留队列并等待联网。
- 成功响应：`201 {"ok":true,"id":"...","receivedAt":"..."}`。
- 重复提交同一 ID 返回 200，客户端按成功处理。

## 5. 反馈包内容

压缩后不超过 5MB。

```
feedback.json        类型、描述、入口、版本/渠道、设备型号、连接模式、会话状态（≤64KB）
report.txt           精简诊断摘要（已脱敏，≤1.5MB）
logs/                最近最多 3 个会话日志，总计 ≤1.5MB
logs/wheel-keys.log  方控日志（如存在，≤128KB）
crash/last-crash.txt 最近一次崩溃记录（如存在，≤256KB）
logcat/logcat.txt    有权限时采集的过滤 logcat（≤512KB）
manifest.json        每个条目的状态、字节数、SHA-256、截断原因
README.txt           内容说明与隐私说明（≤8KB）
```

明确排除：

- StableClientId、Android ID
- 手机名称、蓝牙地址
- SSID、IP 地址
- 配对信息、热点密码
- 协议载荷
- 系统库、APK、系统组件清单
- 设置数据库
- 完整 logcat 历史

脱敏规则：

- 所有文本先经过 `DiagnosticRedactor`。
- 额外按当前手机名称、手机地址做字面量替换。
- 用户填写的问题描述原样保留，但页面提示不要填写个人信息。
- `report.txt` 不包含 StableClientId 行。

现有的“保存诊断报告”和完整 `DiagnosticBundle` 保持不变，反馈包是独立的轻量路径。

超过 5MB 时按顺序丢弃：先丢 logcat，再丢最旧的会话日志；仍超限时只保留 `feedback.json`、`report.txt`、`crash/last-crash.txt`、`manifest.json` 和 `README.txt`，并在 manifest 中记录丢弃原因。

## 6. 后端设计

复用 `update-service` 的 Cloudflare Pages Functions + R2 + KV 基础设施。

### 6.1 公开上传接口

```
POST /api/v1/apps/diplay/feedback
```

处理流程：

1. 校验请求体 ≤6MB、zip ≤5MB、描述 ≤2000 字符、类型白名单、反馈 ID 为 32 位小写十六进制。
2. 使用 `fflate` 读取 zip 目录，拒绝路径穿越、条目数超过 64、解压后总大小超过 20MB 的包。
3. 只提取 `feedback.json`、`report.txt`、`manifest.json` 做校验和预览，不解压日志。
4. 校验 `feedback.json` 与 multipart `meta` 的 ID、类型、版本一致，校验 `bundleSha256`。
5. 校验 `manifest.json` 存在，`report.txt` 存在且为文本。
6. 限流：每个 IP 每小时 5 次、每天 20 次，使用现有 `RATE_KV`，TTL 分别 2 小时和 2 天。IP 不在反馈包、索引或管理台中保存。
7. Cloudflare WAF 对 `/api/v1/apps/*/feedback` 增加边缘限流规则。
8. 幂等：同一反馈 ID 已存在时直接返回 200，不覆盖已有对象。
9. 先写 zip，再写索引；索引失败时尽力删除 zip，避免管理台出现悬空记录。
10. 返回 `201`；超限返回 `413`；格式错误返回 `422`；限流返回 `429` 并带 `Retry-After`。

### 6.2 存储结构

复用现有私有 `META` R2 桶：

```
feedback/diplay/objects/{id}/bundle.zip
feedback/diplay/index/{receivedAtMs}-{id}.json
```

索引对象内容：

```json
{
  "schemaVersion": 1,
  "id": "...",
  "receivedAt": 1760000000000,
  "category": "connection",
  "description": "...",
  "app": { "versionName": "...", "versionCode": 4000, "channel": "beta" },
  "device": { "manufacturer": "...", "model": "...", "board": "...", "androidRelease": "..." },
  "session": { "mode": "wireless", "state": "failed" },
  "bundleKey": "feedback/diplay/objects/{id}/bundle.zip",
  "bundleBytes": 1234567,
  "bundleSha256": "...",
  "reportPreview": "最多 64KB 的 report.txt 文本",
  "previewTruncated": false
}
```

- 保留期 90 天，通过 R2 生命周期规则作用于 `feedback/` 前缀。
- 管理台删除立即删除 zip 和索引。
- 后续反馈量增大时可拆到独立 R2 桶，接口不变。

### 6.3 管理接口

所有管理接口复用现有 `isAdmin` 会话校验。

```
GET    /api/v1/admin/feedback?limit=50&cursor=...
GET    /api/v1/admin/feedback/{id}
GET    /api/v1/admin/feedback/{id}/bundle
DELETE /api/v1/admin/feedback/{id}
```

- 列表读取索引对象，按 `receivedAt` 倒序，默认 50 条。
- 详情返回索引内容和 `reportPreview`。
- 下载流式返回 R2 对象，设置 `Content-Disposition: attachment` 和 `X-Content-Type-Options: nosniff`。
- 删除返回 `{ "ok": true }`。

### 6.4 契约、依赖与运维

- 新增 `update-service/schema/feedback-v1.schema.json`，约束 multipart `meta`、`feedback.json` 和索引对象。

## 7. 管理台

在现有 `/admin/` 增加“用户反馈”标签页。

列表列：

- 接收时间
- 类型
- DiPlay 版本
- 设备型号
- 包大小
- 描述摘要

功能：

- 按时间范围、类型、版本筛选
- 关键词过滤（当前页或已加载数据）
- 按时间倒序，分页 50 条
- 详情面板展示完整描述、设备/版本/会话信息、`report.txt` 预览
- 下载 zip
- 删除，带二次确认
- 空状态和加载失败提示

安全：

- 所有内容以纯文本插值展示，不使用 `v-html`。
- 下载走管理会话 Cookie，不生成公开 URL。
- 本期不做状态流转、指派、备注、回复用户。

## 8. 隐私

- 完全匿名：不收集账号、手机号、微信、邮箱或其他联系方式。
- 不包含 StableClientId、Android ID 或设备持久标识。
- 每次反馈使用新的随机 ID，不用于跨反馈关联。
- 不把 IP 写入反馈包、索引或管理台；仅 `RATE_KV` 中保留短期 TTL 的限流计数。
- 日志中的蓝牙地址、IP、SSID、配对信息、热点密码、协议载荷会被移除或替换。
- 反馈包内 README 说明采集范围、脱敏规则和保留期。
- 页面提示用户不要在描述中填写个人信息。
- 本地待发送记录只保存在车机应用私有目录，上传成功或用户删除后清除。
- 本地已发送记录只保留反馈编号、时间、类型和状态，不保留描述、日志或设备信息；最多 10 条、30 天，用户可清空。
- 后端保留 90 天，管理台可提前删除。

## 9. 失败与边界处理

| 场景 | 客户端行为 | 服务端行为 |
| --- | --- | --- |
| 生成包失败 | 提示错误，留在表单，可重试 | 不涉及 |
| 无可用互联网 | 入队，按钮显示“保存，联网后发送”，联网后自动上传 | 不涉及 |
| 上传超时/5xx/429 | 入队并自动重试 | 429 带 Retry-After |
| 4xx 永久拒绝 | 标记失败，保留 7 天，可手动重试或删除 | 返回明确错误码 |
| 队列满 5 条待上传 | 拒绝新反馈并提示 | 不涉及 |
| 磁盘不足 | 提示并保留旧反馈 | 不涉及 |
| 重复上传 | 按成功处理 | 幂等，不覆盖 |
| 非法 zip/meta | 不涉及 | 422 |
| 包过大 | 生成阶段按顺序截断日志；仍超限则只保留必需文件 | 413 |
| 无可用互联网时点重试 | 弹网络提示，可跳转系统网络设置 | 不涉及 |
| CarPlay 会话活跃 | 自动重试暂缓，用户主动提交不受影响 | 不涉及 |
| 管理台未登录 | 不涉及 | 401 |

## 10. 测试与验收

### 客户端单测

- 反馈包包含必需文件，且不包含 StableClientId、手机名称、蓝牙地址、IP。
- 日志截断顺序：先丢 logcat，再丢最旧日志，不丢 `report.txt`、`feedback.json`、`crash`。
- 5MB 上限和 manifest 状态正确。
- 队列原子性、最多 5 条待上传、永久失败 7 天清理。
- 上传成功后删除日志包并写入已发送记录；已发送记录只含编号、时间、类型和状态。
- 已发送记录最多 10 条、30 天，支持单条删除和清空。
- 上传状态机：成功、429、5xx、4xx、超时。
- multipart 格式和 `bundleSha256` 正确。
- `FeedbackConnectivity` 只接受经过验证的互联网网络，仅有本地 Wi-Fi 时判定为不可上传。
- `FeedbackUploadWorker` 在没有可用互联网时不发起请求并返回重试。
- 待处理数量统计包含待上传、上传中、自动重试和永久失败。

### Robolectric / UI

- 分类必选时发送按钮不可用；连接失败入口预选“连接”。
- 描述可选，空描述可提交。
- 上半部布局在窄屏和大字体下仍可见输入框与发送按钮。
- 在线/离线时按钮文案分别为“发送反馈”和“保存，联网后发送”。
- 提交后状态切换、反馈编号展示、待上传数量展示。
- 用户提前离开页面后，后台上传成功仍能在“已发送”标签中看到结果。
- 反馈记录页“待处理/已发送”标签、四种待处理状态、已发送记录和空状态正确。
- 设置首页 Diagnostics 卡片和侧栏角标显示待处理数量。
- 反馈记录页重试、全部重试、删除和空状态正确。
- 离线点重试弹出网络提示，“打开网络设置”在可用时跳转正确。
- 连接失败面板按钮只在失败时显示。
- 所有新增 `feedback_*` 字符串在所有 locale 中存在。

### 后端测试

- 正常上传、幂等重复上传。
- 超限、非法类型、非法 ID、缺失 `feedback.json`/`report.txt`。
- zip 路径穿越、条目过多、解压后超限。
- 限流 429。
- 未登录管理接口 401。
- 列表、详情、下载、删除。
- `reportPreview` 截断和管理台转义。

### 实车冒烟

- 断网提交，页面显示“保存，联网后发送”，联网后自动上传。
- 仅连接 CarPlay 本地 Wi-Fi、无外网时，页面判定为未联网且不上传。
- 从系统网络设置返回后，网络状态和重试按钮自动刷新。
- 上传时 CarPlay 活跃，确认自动重试延后到会话结束。
- 提交后立即离开页面，后台上传成功，再进入反馈记录页能在“已发送”中看到编号和结果。
- 设置首页和侧栏角标随待处理数量变化。
- 反馈记录页重试、全部重试、删除和离线网络提示正确。
- 中英文界面、阿拉伯语 RTL、大字体。
- 键盘弹出时输入框、类型选择器和发送按钮均可见。
- 队列满、磁盘不足、服务端 429 的提示。

## 11. 上线顺序

1. 完成 `update-service` 上传接口、管理接口、管理台、schema 和文档。
2. 配置 WAF 反馈上传限流规则和 R2 `feedback/` 前缀 90 天生命周期规则。
3. 部署 `update-service`。
4. 发布 beta 包，观察 1–2 周上传成功率、429 比例、包大小和存储量。
5. 确认管理台查看流程、网络提示和反馈记录页可用后进入 stable。
6. 不新增服务端密钥；反馈接口匿名，依赖限流、大小限制、WAF 和管理台删除控制风险。

- 完整系统组件上报
