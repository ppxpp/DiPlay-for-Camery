# 播放后立即暂停的日志排查

复现后尽快导出诊断包，提供点击播放的大致时间，并说明导航、原生音乐是否有声音。

- `AUDIO_CONTROL` 用 attempt/run/session 区分连接，event 为控制器内事件编号，wallMs 用于对齐视频，elapsedMs 用于计算间隔。
- command 使用媒体 HID 编号：1 播放、2 暂停、3 播放/暂停切换、4 下一首、5 上一首。source 指明方向盘服务、媒体会话、车机伴生组件、宿主按键或音源恢复。CarPlay 画面内的触摸由手机解释，不会生成本地媒体命令。
- outcome 区分排队、派发、发送返回、异常和拒绝。send_returned 不代表手机已确认或执行；失败也不能排除部分 HID 报文已经发出。
- phonePlaying 记录手机状态变化及最近派发命令、来源和间隔；时间相近仅表示相关，不能单独证明因果。没有本地暂停命令也不能排除手机、其他应用或蓝牙链路的控制。
- `Audio: focus` 的 action 记录焦点回调采取的音量策略；`media gain` 记录实际音轨增益应用结果，不代表扬声器已发声。
- `Pioneer source verified` 记录请求后的实际音源；`Audio source recovery` 的变化记录帮助识别后续被切回的情况。观察器按原有条件运行，不能保证覆盖所有车机。

这些事件复用现有诊断日志出口，不记录歌曲名称、设备地址或完整堆栈。日志不能识别所有系统焦点拥有者，也不能单独证明物理断电原因；整机重启仍需另采 bootreason 和系统允许读取的 pstore/last_kmsg、MCU 电源记录。
