# 蓝牙模块排查策略

本模块用于快速验证技术路线。遇到实机异常，先从固件查深层原因，再针对性设计修改：

1. 先保存版本、目标设备、原配置、调用返回值和现场日志；条件允许时补充底层状态与包级记录。
2. 优先分析与实车一致的二进制，核对文件哈希、实际调用链、对象/端口/UUID选择、回调注册与分发、锁和等待、错误分支及恢复逻辑。ROM与实车版本不同时，先比较关键代码，不能假定地址兼容。
3. 将“请求受理、上层缓存、底层连接标志、真实协议收发、手机认证、Wi-Fi接管”分别取证。返回0、注册成功、缓存变为1均不等于CarPlay成功。
4. 找到具体证据后，做最小可运行的修改。优先复用DiPlay已有协议与root调度；root修复只针对已核实固件和服务，不在应用内另起硬件蓝牙栈。
5. 对未知布局、目标不符、其他设备占用、取消和超时明确停止；保存原配置并设计恢复入口。不盲目清零底层状态，不无限重试。
6. 只做本次变更必要的构建/检查。必须实机才能回答的问题明确列出，不用本地测试或静态反汇编冒充实机成功。
7. 将阶段结果最后汇总至已有中文日期时间报告；临时分析材料放在`agent_docs/temporary/`，不堆积旧报告。

用户要求保持不休眠时，可在工作期间临时启用；工作完成后停止本次启动的后台任务和防休眠进程，允许本机休眠。
